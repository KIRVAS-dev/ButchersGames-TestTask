# Refactor

Когда читать: триггер `Refactor` / `refactor` / `refactoring` / «рефактор» / «рефакторинг» — в начале сообщения или отдельной строкой. Вне триггера — не применять.

**Только отчёт с рекомендациями.** Правки кода — по отдельному ok ([../../CLAUDE.md](../../CLAUDE.md) §1). Не путать с review ([../../CLAUDE.md](../../CLAUDE.md) §4): Review = соответствие rules / баги; Refactor = каталог улучшений структуры (гл. 24.3 Code Complete + WebGL-Template).

Опора: design/codestyle/exceptions/architecture ([../../CLAUDE.md](../../CLAUDE.md) §3, hub). Rename C# — только через [rider-mcp.md](rider-mcp.md) при implement.

## Scope (обязательно разрешить)

Приоритет сверху вниз; **не расширять** за пределы:

1. **Явные пути / вложения** в сообщении
2. **Имена файлов / фич / папок**, названные пользователем
3. **Файлы коммита / diff** — если сказано «в коммите», «в diff», «staged», «последний коммит»; иначе спросить
4. Scope неясен → **один** уточняющий вопрос; не рефакторить «весь проект»

Читать файлы **целиком** (не только hunk), если они в scope.

## Процедура

1. Зафиксировать scope (список путей)
2. Пройти каталог ниже; finding только при **реальном** запахе в scope
3. Учитывать WebGL-Template: слои Model/Service/View, InputHandler, UniTask, typed exceptions, `_camelCase`/`reformat_file`
4. **Не** предлагать: микрооптимизации без evidence; правки ради вкуса; изменение публичного Api без нужды; ломать `[SerializeField]` порядок без причины
5. Выдать отчёт; стоп до ok на implement

## Каталог рекомендаций (24.3 → C# / Unity)

### Данные / переменные

| Запах | Рекомендация |
|---|---|
| Магическое число / литерал | Named `const` / `static readonly` / config SO |
| Плохое / короткое имя (`temp`, `x`, `data`) | Rename (Rider); одна цель на переменную |
| Сложное выражение без имени | Intermediate local / explaining variable |
| Одна переменная — несколько ролей | Разбить на несколько locals |
| Параметр используется как рабочая переменная | Локальная копия; параметр не мутировать |
| Набор кодов типов (`0/1/2`) | `enum` / typed id; разное поведение → полиморфизм / стратегия |
| Параллельные массивы / «запись» полями | `record` / class DTO; правила — в Service, не в DTO |
| Голая коллекция с инвариантами снаружи | Инкапсулировать (тип-обёртка / Api) |

### Операторы / ветвление / циклы

| Запах | Рекомендация |
|---|---|
| Сложный boolean в `if` | Именованный `bool` или bool-метод (`Is`/`Can`/`Has`) |
| Дубли веток / одинаковые хвосты | Consolidate; extract общего |
| Глубокий `if/else` | Guard / early exit; typed exception на invalid command |
| `switch`/лесенка по типу с логикой в ветках | Полиморфизм, table (`Dictionary`/SO), `switch` expression как тонкий диспетчер |
| Цикл с несколькими целями | Одна цель; упростить условие; вынести тело |
| Null-проверки повсюду | Явный optional/`Try`; не глотать ошибки query/command |

### Методы / routines

| Запах | Рекомендация |
|---|---|
| Длинный / несколько задач | Extract method; сохранить связность |
| Лишняя обёртка без абстракции | Inline method |
| Почти одинаковые методы | Parameterize / общий Helper (stateless) |
| Query меняет состояние | Разделить command и query ([exceptions.md](exceptions.md)) |
| Много разрозненных параметров | `record`/DTO/options; ≤ ~7 ориентир |
| Метод знает чужие внутренности / глобалы | Через DI/порты; Api, не детали View |
| Смесь init + I/O + расчёт | Разнести по методам/слоям |

### Классы / типы / слои (WebGL-Template)

| Запах | Рекомендация |
|---|---|
| God-класс / смешанные ответственности | Extract class; проверить слой (Core vs ViewComponents vs Input) |
| Наследование «ради кода» | Композиция / делегирование |
| Логика в DTO / View / Provider | Перенести в Service |
| View → Service напрямую | Через InputHandler |
| ViewComponents → Model mutation | Только Service меняет state |
| Дублирование между фичами | Shared через Api/Helper по architecture |
| Публичный Api размыт | Сузить контракт |

## Формат отчёта

1. **Scope** — список файлов
2. **Вердикт** — рефакторинг не нужен / есть рекомендации / много запахов
3. Каждая рекомендация: `Severity (Major / Minor / Nit)` — `Файл:строка` — запах — действие — зачем — риск при apply
4. **Не** предлагать правки вне scope
5. Нет запахов → явно «рефакторинг не требуется»
6. В конце (если есть Major/Minor): краткий порядок apply; implement — только после ok

## Не делать

- Мутировать код / git / сцены по триггеру рефакторинга
- Подменять Review полным compliance-аудитом
- «Приведи весь модуль к идеалу» без границ
